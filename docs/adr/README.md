# ADR (Architecture Decision Record)

設計上の判断を記録する場所。

## なぜ書くのか

**「なぜこうしたか」を書けないなら、まだ理解していない証拠。**
実装者ではなく設計者を目指すなら、この習慣が最大の投資になる。

## 書くタイミング

- 技術を選定したとき（DB、認証方式、ライブラリ）
- 設計を決めたとき（Aggregate境界、座標の持ち方、API設計）
- **後から「なぜこうしたんだっけ」と思いそうなとき**

## ファイル名

`0001-postgresql-を選んだ理由.md` のように連番 + 内容。

## テンプレート

```markdown
# 0001. <決定の内容>

- ステータス: 採用 / 却下 / 置き換え済み（→ ADR-00XX）
- 日付: YYYY-MM-DD

## 背景

何を決めなければならなかったのか。制約は何か。

## 選択肢

1. 案A — 
2. 案B — 
3. 案C — 

## 決定

案Xを採用する。

## 理由

なぜそれを選んだか。他案を落とした理由も書く。

## 結果・トレードオフ

これにより何が良くなり、何を諦めたか。
将来どうなったら見直すべきか。
```
