# レッスン9: セキュリティの勘所

学習日: 2026-09-30

**ゴール: 「後回しで」と言ってはいけないものを見分ける。**
PMがセキュリティの専門家になる必要はない。判断を誤らなければ十分。

## 「セキュリティは後でまとめて」への答え方

❌ 「手戻りが多いので、先にやることをお勧めします」→ 平行線になる

⭕ **「全部」ではなく「分ける」**

> 「一括で後回しにはできません。ただし全部を今やる必要もありません。
> **今やるもの**：権限、HTTPS、パスワード、操作ログ、XSS対策。後から入れると作り直しか、取り返しがつかない。
> **後でいいもの**：ログインロック、脆弱性診断。後から足せて既存に影響しない。
> 二要素認証は、管理者だけ先にやりましょう。」

### セキュリティの3区分（レッスン6の判断軸 + 1）

| 区分 | 例 |
|---|---|
| 後から足せる | ログインロック、脆弱性診断 |
| 後から変えるしかない | 権限、パスワード方式 |
| **後からでは取り返しがつかない** | **操作ログ、漏洩したデータ** |

3つ目がセキュリティ特有。**漏れたデータは回収できない。**

## 仕分け

| 対策 | 時期 | 理由 |
|---|---|---|
| 権限チェック | **前** | 土台。後付けは作り直し |
| HTTPS | **前** | 設定だけ。やらない理由がない |
| パスワードのハッシュ化 | **前** | 後から変えると全員の再設定が必要 |
| ログイン失敗でロック | 後 | 後から足せる |
| **操作ログ** | **前** | **過去に遡って記録できない** |
| 二要素認証 | 判断 | 下記 |
| 脆弱性診断 | 後 | リリース直前〜直後 |
| XSS対策 | **前** | 標準で防げるが、崩す書き方をしないルールが要る |

### 操作ログは最も見落とされる

```
リリース3ヶ月後、施工図が外部に流出
→ 「誰がダウンロードしたか」を調べたい
→ 操作ログを取っていなかった → 永久に分からない
```

**存在しなかったデータは作れない。**（レッスン5の裏返し）

### 二要素認証はトレードオフ

| 立場 | 理由 |
|---|---|
| 前 | 協力会社が多数出入り、図面は機密 |
| 後 | 現場で毎回コード入力は嫌がられ、**使われなくなる** |

落としどころ: **管理者と発注者だけ必須、作業員は任意。** PMが決める領域。

## 「社内と協力会社だけだから安全」は成り立たない

| 建設現場の実態 | リスク |
|---|---|
| 協力会社が数十社、作業員が数百人入れ替わる | アカウント停止漏れが必ず起きる |
| 工期が終わると人がいなくなる | **誰も止めない** |
| 1台の端末を複数人で共有 | 誰の操作か分からない |
| 現場事務所のPCがログインしっぱなし | 誰でも触れる |
| **協力会社は競合の現場も掛け持ち** | 悪意がなくても図面が他社に流れる経路になる |

### 対策

| 実態 | 対策 |
|---|---|
| 停止漏れ | **工期終了で自動的にアクセス終了**（レッスン5のメンバーシップ期間） |
| 端末共有 | 自動ログアウト、個人アカウントの徹底 |
| 図面の持ち出し | ダウンロード制限、**閲覧者名入りの透かし** |

> **良い設計は、セキュリティを「人の注意」に頼らない。**
> 「削除ではなく参加期間の終了」というデータ設計が、そのままセキュリティ対策になる。

## 持ち帰り: 必ず聞くこと

| 質問 | なぜ |
|---|---|
| **操作ログは取っていますか？ 何を記録しますか？** | 後から取り戻せない |
| **現場を離れた人のアクセスは、誰がいつ止めますか？** | 人に頼ると必ず漏れる |
| パスワードはどう保存していますか？ | 後から変えると全員再設定 |
| 図面のダウンロードは誰でもできますか？ | 持ち出し経路 |
| 端末を共有する運用はありますか？ | 操作者の特定 |
| 脆弱性診断はいつ、誰がやりますか？ | 予算とスケジュール |
