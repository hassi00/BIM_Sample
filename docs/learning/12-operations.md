# レッスン12: 運用・監視・障害対応

学習日: 2026-10-08

**ゴール: 「リリースは終わりではない」を具体的に理解する。**
システムはリリースした日から、毎日使われ、毎日何かが起きる。

## 障害の最中: PMにしかできないこと

朝7時半、監督から「アプリが開かない。8時の朝礼で図面を使うのに」。

まず**影響範囲の確認**。電話は1本でも、困っているのは50現場かもしれない。

原因はエンジニアが調べる。その間にPMがやること:

| やること | 内容 |
|---|---|
| **① 現場の業務を止めない** | 「紙の図面を印刷してください」「PDFを直接送ります」など**代わりの手段**を案内 |
| **② 連絡を一本化する** | 「状況は私から30分ごとに連絡します」。エンジニアに電話を殺到させない |
| ③ 判断する | 修正を待つか、前のバージョンに戻すか |

監督が困っているのは「アプリが開かない」ことではなく「**朝礼で図面が使えない**」こと。
朝礼が紙の図面で予定通りできれば、業務への影響はゼロにできる。**業務を知るPMにしかできない。**

> **障害対応でのPMの役割:**
> **エンジニアが直すことに集中できるよう、それ以外を全部引き受ける。**

## 監視: ユーザーの電話で障害を知るのは最悪の形

「このシステムは、こちらが言わないと気づかない」と思われる。

| 監視 | 何が分かるか |
|---|---|
| **死活監視** | 1分ごとにアクセスして、そもそも開くか |
| **エラー率** | 普段0.1%が5%に上がった |
| 応答時間 | 普段0.5秒が5秒に（レッスン10のピーク） |
| 処理待ちの件数 | 変換待ちが溜まっている（レッスン8） |

### アラートが出ても気づけないことがある

```
朝6時に障害 → アラートはエンジニアのメールへ
→ エンジニアは9時出社 → 7時半に監督から電話
```

建設現場のピークは朝7時台。一般的なIT企業の始業より早い。

> **PMが決めること: 「何時から何時まで、誰がアラートを受けるか」**
> 現場が7時から使うなら、6時半には誰かが確認できる体制が要る。
> それは人件費。業務の時間帯を知っているPMが、費用とセットで決める。

## 復旧後: 個人ではなく仕組みを問う

### 個人を責めると障害が隠される

```
エンジニアが注意される
→ ミスを報告しにくくなる
→ 小さな異常を見ても「自分のせいかも」と黙る
→ 問題が大きくなってから発覚する
```

### 原因は個人ではない

今回の原因は「前日の夕方に入れた修正」。
レッスン11で、前日の夕方の修正は一番危険だと学んだ。

| ❌ 個人の問題として問う | ⭕ 仕組みの問題として問う |
|---|---|
| なぜミスをしたのか | **なぜ前日の夕方に修正を入れられる仕組みだったのか** |
| なぜ確認しなかったのか | **なぜ確認しなくても本番に出せる仕組みだったのか** |
| もっと注意しろ | **注意しなくても防げる仕組みにする** |

レッスン9「良い設計は人の注意に頼らない」はプロセスにも当てはまる。

### 振り返り（ポストモーテム）

| 項目 | 内容 |
|---|---|
| 何が起きたか | 時系列で事実を書く |
| 影響 | 何現場、何人、何分 |
| 原因 | **なぜそれが起き得たか**（人ではなく仕組み） |
| 再発防止 | 仕組みをどう変えるか |

再発防止の例:
- リリース前日の15時以降は本番への反映を禁止する
- ステージングで確認していないものは本番に出せない設定にする
- **問題が出たら、すぐ前のバージョンに戻せる手順を用意する**

最後が特に重要。前のバージョンに戻せれば、8時15分ではなく7時35分に復旧でき、朝礼に間に合っていたかもしれない。

> **障害の振り返りでは、誰がやったかではなく、なぜそれが起き得たかを問う。**
> PMが率先して「個人を責めない」姿勢を見せると、チームは問題を早く報告するようになる。
> **エンジニアからの信頼を得るうえで、12回の中で一番効く話。**

## 持ち帰り: 必ず聞くこと・決めること

| 質問 | なぜ |
|---|---|
| **障害が起きたら、現場は何で代用できますか？** | 業務を止めない |
| **アラートは何時から何時まで、誰が受けますか？** | 現場のピークは朝7時台 |
| 何を監視していますか？ | 電話で知る前に気づく |
| **前のバージョンにすぐ戻せますか？** | 最短の復旧手段 |
| 障害の連絡窓口は誰ですか？ | エンジニアを調査に集中させる |
| 振り返りの場はありますか？ | 仕組みで再発を防ぐ |
