# 第2部: 道具編 + 案件シミュレーション

開始: 2026-10-08

## 目的

12回のレッスン（PMとしての判断）を終えたうえで、次の2つを身につける。

| 段 | 内容 |
|---|---|
| 1 | PMとして判断できる | ✅ レッスン1〜12 |
| 2 | **開発の道具と流れが分かる**（エンジニアが毎日何を使い、どう作業しているか） |
| 3 | **簡単な設計が自分で書ける**（データモデル、API） |

到達点は「エンジニアと同じ言葉で話せるPM」。プロの開発者になることは目指さない。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 開発環境 | **自分のWindows PCに実際に入れて動かす** |
| 開発パートの深さ | **設計は自分で書く。コードは Claude が書き、自分は読んでレビューする** |
| 順番 | **道具編とシミュレーションを混ぜて進める**（必要になった道具をその場で学ぶ） |
| ペース | **1回1時間・週2〜3回** |

## 案件

**配筋検査アプリ**（中堅ゼネコン、社員800人、同時稼働の現場 約40）

- 現状: 紙のチェックシート + デジカメ → 事務所でExcel転記 → 写真整理 → 報告書
- 期待: 現場でタブレット入力・撮影 → そのまま報告書
- 体制: 社内エンジニア3名、PMは自分

## 進行表（全12回、約4〜6週間）

| 回 | 種別 | 内容 | 必要な道具 |
|---|---|---|---|
| 1 | 場面1・PM | キックオフ: 依頼者から話を聞く | なし |
| 2 | 道具1 | 開発環境の全体像 + VS Code / Git のインストール | |
| 3 | 場面1・開発 | データモデルを設計する（ER図を書く） | VS Code |
| 4 | 道具2 | Git と GitHub（自分の設計をコミット・PR） | Git |
| 5 | 場面2・PM | 見積もりレビュー | |
| 6 | 道具3 | ローカルで動かす（.NET / Node.js / Docker） | 全部 |
| 7 | 場面2・開発 | API設計 + コードを読む | 全部 |
| 8 | 場面3・PM | 仕様変更が来る | |
| 9 | 場面3・開発 | マイグレーション（既存データの移し方） | 全部 |
| 10 | 道具4 | チームの道具（タスク管理・CI・ドキュメント） | GitHub |
| 11 | 場面4 | リリース判定 + バグを読んで直す | 全部 |
| 12 | 場面5 | 障害対応 + ログを読む + 振り返り | 全部 |

## 進め方

- アクティブラーニング: 問いが先、答え合わせが後
- 場面ごとに講評（地雷の発見 / 質問の質 / 伝え方 / 判断の根拠）。点数はつけない
- **前の場面の判断が、後の場面に影響する**
- 途中で「一旦止めて質問」「ヒントがほしい」「持ち帰ります」はいつでも可
- 記録は `docs/simulation/` に残す
